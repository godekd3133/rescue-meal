# 제품 개요

## 해결하려는 문제

냉장고에 무엇이 남았는지 기억하기 어렵고, 구매 내역을 일일이 입력하기 번거롭습니다. 같은 상품도 구매일·보관 장소·개봉 상태가 다르므로 상품 이름만으로 묶으면 실제 재고를 관리하기 어렵습니다.

Rescue Meal은 입력 부담을 줄이면서 구매 단위 재고와 날짜의 출처를 보존합니다. 홈의 Rescue Queue는 먼저 확인하거나 사용할 재료를 보여주고, 식단은 현재 재고와 부족한 재료를 함께 제공합니다.

## 기능 범위

| 영역 | 사용자에게 제공하는 기능 |
| --- | --- |
| 등록 | 영수증 이미지·PDF 검토, 바코드 후보 조회, 식품 라벨 날짜 검토, 직접 입력 |
| 재고 | 구매 단위 lot, 부분 수량 소비·이동·개봉, 폐기, 검색, 사용자 정의 보관 위치 |
| 날짜 | 표시 날짜의 종류·출처·보관 조건 확인, 수정 이력, 추정 사용 우선순위 |
| 식단 | 재고 기반 미리보기, 대안 메뉴, 3일 계획, 저장·재조회, 사용량 확인 후 조리 완료 |
| 장보기 | 부족 재료와 직접 추가 항목, 체크·삭제·입고 |
| 계정 | 게스트·회원 workspace, 명시적 게스트 데이터 이전, 복구·내보내기·삭제 |
| 알림·연동 | 앱 내 확인 알림, 선택적 Web Push·Grocy 동기화 |

## 날짜를 읽는 방법

`소비기한`, `유통기한`, `품질유지기한`, 제조일 등의 종류를 보존합니다. 상품 데이터베이스가 알려주는 일반 상품 정보는 개별 포장의 날짜가 아닙니다. OCR이 날짜처럼 보이는 숫자를 읽었더라도 종류와 원본을 확인해야 합니다.

보관 이동이나 개봉으로 추정 우선순위가 바뀔 수 있습니다. 이 과정에서 포장 표시 날짜를 임의로 새 소비기한으로 바꾸지 않습니다. 알레르기 정보와 실제 식품 상태도 사용자가 별도로 확인해야 합니다.
