# 주요 사용자 흐름

## 등록 → 검토 → 재고 반영

1. 영수증·라벨 촬영 또는 파일 선택, 바코드 스캔, 직접 입력 중 하나를 선택합니다.
2. 이미지 품질과 인식 결과를 확인합니다. 상품·수량·날짜는 검토 후보로 제시됩니다.
3. 실제 원본과 비교하고 잘못 읽은 값이나 보관 위치를 수정합니다.
4. 사용자 확인 후 구매 단위 lot으로 반영합니다.

텍스트 레이어가 있는 영수증 PDF는 text extraction을 사용하고, 스캔 PDF는 제한된 페이지를 렌더링해 OCR로 처리합니다. OCR 실패·상품 검색 실패를 임의의 성공 결과로 바꾸지 않습니다. 바코드 상품 정보도 포장의 실제 날짜를 대신하지 않습니다.

## 재고 상세 → 이동·개봉·소비

상세에서 상품 정보, 표시 날짜의 출처, 보관 장소와 이력을 확인합니다. 일부 수량만 이동·개봉·소비할 수 있으며, 이벤트 기록과 남은 수량을 보존합니다. 같은 이름의 식품도 서로 다른 구매 lot일 수 있습니다. 폐기는 사용자가 실제 상태를 확인한 뒤 진행합니다.

다른 기기의 변경을 감지하면 편집 중인 상세 입력은 유지하고 최신 상태 확인을 안내합니다. 새 상태를 확인하기 전 무조건 다시 저장하면 충돌할 수 있습니다.

## 재고 → 식단 → 조리 완료

1. 현재 재고와 선호 설정으로 식단을 미리 봅니다.
2. 대안 메뉴·3일 계획·부족 재료를 확인합니다.
3. 원하는 계획을 저장합니다.
4. 실제 사용량을 확인하고 조리 완료를 기록합니다.
5. 완료된 계획과 재고 차감 결과를 다시 확인합니다.

미리보기와 저장, 조리 완료는 서로 다른 단계입니다. 오래된 재고 snapshot으로 저장하려 하면 최신 재고 확인이 필요할 수 있습니다. 장보기에는 식단에서 부족한 재료와 직접 추가한 항목이 함께 나타납니다. 입고는 사용자 확인 후 재고로 반영합니다.

## 계정·오프라인

게스트 사용 데이터의 회원 이전은 명시적으로 선택합니다. 내보내기·계정 복구·삭제는 각 계약을 따릅니다. 오프라인은 최근 화면을 읽는 범위이며, 연결을 복구한 뒤 실제 변경을 진행합니다.
