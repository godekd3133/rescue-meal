# Rescue Meal 제품 흐름

## 1. 대상 사용자와 목표

### 1차 사용자

- 장을 본 뒤 식재료 등록이 번거로워 냉장고 관리 앱을 포기한 1~2인 가구
- 냉장·냉동·실온 식품이 섞여 있고 무엇부터 먹어야 할지 자주 놓치는 사용자
- 식재료를 버리는 시점에야 같은 재료가 있었다는 사실을 발견하는 사용자

### 사용자가 달성해야 하는 결과

1. 장을 본 뒤 1장의 영수증으로 여러 식재료를 빠르게 초안 등록한다.
2. 모호한 항목만 확인해 잘못된 자동 입고를 막는다.
3. 같은 상품이라도 구매 묶음·보관 위치·개봉 상태별로 구분한다.
4. 실제 표시 날짜와 추정 소비 우선일의 차이를 이해한다.
5. 오늘 먼저 사용할 재료와 만들 수 있는 식단을 확인한다.
6. 사용·폐기 결과를 남겨 추천 정확도를 평가한다.

## 2. 핵심 흐름 A — 영수증 자동 입고

### A1. 입력

- 종이 영수증 카메라 촬영
- 영수증 이미지 업로드
- 전자 영수증 PDF 또는 스크린샷

촬영 단계에서 잘림·흐림·과노출·기울기를 검사하고, 필수 영역이 누락되면 다시 촬영하게 합니다.

### A2. 문서 추출

영수증을 다음 구조로 추출합니다.

```text
store_name
receipt_number
purchased_at
total_amount
line_items[]
  raw_name
  quantity
  unit_price
  total_price
  internal_sku?
  weight?
```

매장별 영수증 레이아웃이 다르므로 범용 AI 하나에 의존하지 않습니다.

- PaddleOCR: 텍스트·위치·신뢰도 추출
- invoice2data 또는 자체 템플릿: 매장 식별 및 라인 구간 파싱
- 팀 고유 parser: 한국 영수증의 할인·취소·중량·다중 구매 후처리

### A3. 상품 매칭

영수증의 `서울우유1L`, `대파1단`, `닭가슴살*2` 같은 축약명을 다음 순서로 매칭합니다.

1. 사용자가 이전에 확인한 매장별 별칭
2. Grocy 상품·바코드·부모 상품
3. 로컬 상품 사전
4. 식품안전나라 C005 바코드 후보(legacy provenance)
5. Open Food Facts 후보
6. 사용자 검색·신규 상품 생성

영수증 상품명 기반으로 식품안전나라 I1250을 조회할 때는 제조사·품목유형·제품명을 대조하는 review 후보로만 사용합니다. 바코드 endpoint에서 I1250을 직접 호출하지 않습니다.

매칭 결과에는 항상 근거와 신뢰도를 남깁니다.

```text
raw_name: "서울우유1L"
candidate: "서울우유 나100% 1L"
match_source: user_confirmed_alias
confidence: high
```

### A4. 검토

모든 항목을 다시 입력하게 하지 않고, 다음 항목만 검토 대상으로 올립니다.

- 신규 상품
- 후보가 둘 이상인 상품
- 수량이나 중량이 모호한 상품
- 취소·환불 가능성이 있는 음수 라인
- 비식품 후보
- 날짜나 매장 식별이 불확실한 영수증

사용자는 `확정`, `상품 변경`, `제외`, `수량 수정`, `새 상품` 중 하나를 선택합니다.

### A5. 재고 반영

영수증 하나의 확인이 끝나면 각 항목을 독립 stock lot으로 생성합니다. 영수증 재스캔 시 파일 hash, 매장, 구매시각, 총액, 영수증 번호를 조합한 fingerprint로 중복 입고를 차단합니다.

영수증에는 일반적으로 개별 상품의 실제 소비기한이 없으므로 다음 단계를 이어갑니다.

- 표시 날짜가 중요한 포장식품: 날짜 라벨 촬영 요청
- 신선식품: 구매일·보관 위치 확인
- 이전에 등록한 동일 상품: 이전 기본 위치를 제안하되 자동 확정하지 않음

## 3. 핵심 흐름 B — 보관 위치와 상태 이력

### B1. 지원 상태

- 위치: 실온, 냉장, 냉동, 사용자 정의 위치(각 위치는 canonical 보관 분류를 함께 가짐)
- 상태: 미개봉, 개봉, 냉동, 해동, 조리됨, 소비됨, 폐기됨
- 이벤트: 이동, 개봉, 분할, 병합, 소비, 폐기

개봉 이벤트는 발생 시각을 lot의 최초 `opened_at`으로 보존합니다. 일부만 개봉하면 미개봉 parent와 개봉 child를 별도 lot으로 나누며, 표시 날짜가 없는 경우에만 첫 개봉일을 기준으로 보관 우선순위를 다시 계산합니다. 이 값은 실제 포장지 소비기한을 대신하지 않습니다.

사용자는 `김치냉장고`·`냉동 서랍` 같은 이름을 만들어 영수증 검수·직접 입력·장보기
입고·상세 이동에서 선택할 수 있습니다. 사용자 정의 위치 이름은 표시용이며,
`ambient`·`refrigerated`·`frozen` class를 대체하거나 온도 센서·소비기한 판정을
만들지 않습니다.

현재 식품이 다른 위치로 이동했거나 소비된 뒤에도 과거 storage event·장보기 입고
기록이 위치를 참조하면 위치를 삭제하지 않습니다. 이름을 바꾸는 방식으로 과거 기록의
장소를 보존하며, 식품 상세의 최근 기록에는 실제 위치명을 표시합니다. 다른 기기에서
위치를 바꾼 경우 계정 화면은 tab 복귀와 짧은 주기의 revision 확인 뒤 최신 목록을
읽고, 편집 중인 stale 입력을 자동으로 저장하지 않습니다.

### B2. 상품이 아니라 lot에 저장

보관 상태는 상품 master가 아니라 구매 묶음에 속합니다. 같은 우유를 다른 날 샀다면 각각 다른 lot과 표시 날짜를 가집니다.

### B3. lot 분할

일부 수량만 다른 위치로 옮기면 원본 lot을 덮어쓰지 않습니다.

```text
원본: 달걀 10개, 냉장
행동: 달걀 4개를 삶아 냉장 보관
결과:
- 생달걀 6개 lot
- 삶은 달걀 4개 child lot
```

부모·자식 관계와 변환 이유를 기록해야 수량 보존을 검증할 수 있습니다.

### B4. 날짜 처리

날짜는 다음 우선순위로 표시합니다.

1. 사용자가 확인한 포장 표시 날짜
2. GS1 AI로 파싱하고 사용자가 확인한 날짜
3. OCR로 추출하고 사용자가 확인한 날짜
4. 사용자가 직접 입력한 알림일
5. 공개 보관 지침·카테고리 규칙으로 계산한 추정 소비 우선일

표시 날짜는 storage event가 발생해도 수정하지 않습니다. 대신 새 보관 상태에 대한 추정 우선일을 별도로 계산합니다.

## 4. 핵심 흐름 C — Rescue Queue와 식단

### Rescue Score 후보

```text
rescue_score
= 표시 날짜 임박도
+ 구매 후 경과일
+ 개봉·해동 상태 가중치
+ 사용자가 설정한 우선도
+ 레시피 활용 가능성
- 데이터 불확실성 패널티
```

이 점수는 안전 점수가 아니며, 먼저 확인·사용할 항목을 정렬하기 위한 제품 점수입니다.

### 식단 선택

OR-Tools를 이용해 다음 조건을 동시에 고려합니다.

- 폐기 위험 재료 사용량 최대화
- 부족한 재료 구매량 최소화
- 조리 가능 시간 준수
- 메뉴 반복 최소화
- 사용자 제외 재료 준수
- 보유 수량 초과 사용 금지

추천 결과에는 이유를 표시합니다.

```text
오늘 저녁: 시금치 달걀볶음

추천 이유
- 시금치가 구매 후 4일 지남
- 달걀 6개 보유
- 추가 구매 재료 없음
- 예상 조리시간 15분
```

## 5. 주요 실패 상태

- OCR이 영수증을 읽지 못함
- 영수증 하단이 잘림
- 영수증을 두 번 업로드함
- 상품명이 너무 축약되어 후보 없음
- 할인·취소 라인을 상품으로 오인함
- 중량상품 수량을 개수로 오인함
- 사용자가 냉장·냉동 위치를 잘못 선택함
- 날짜는 읽었지만 제조일·포장일·소비기한 의미가 모호함
- 레시피 재료명과 재고명이 연결되지 않음
- 보관 규칙 출처가 없거나 한국 환경에 맞지 않음

각 실패는 무음 자동확정 대신 `확인 필요` 상태로 남겨야 합니다.

## 6. 제품 안전 문구

- `실제 표시 소비기한`: 포장에 표시되고 사용자가 확인한 값
- `추정 소비 우선일`: 보관 이력과 참고 규칙으로 계산한 정리용 값
- `사용자 알림일`: 사용자가 정한 일정

금지 문구:

- `이 날짜까지 안전합니다`
- `사진상 상하지 않았습니다`
- `냉동했으므로 소비기한이 자동 연장됐습니다`
- `추정 소비기한`

권장 문구:

- `포장에 표시된 보관방법과 실제 보관 상태를 확인하세요.`
- `이 날짜는 소비기한이 아니라 먼저 확인할 시점을 제안합니다.`
- `라벨 날짜와 보관 상태가 다르면 제조사 안내를 우선 확인하세요.`
