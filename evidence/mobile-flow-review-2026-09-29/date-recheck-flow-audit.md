# 모바일 날짜 재확인 흐름 점검

## 범위

- Rescue Meal 앱 소유 모바일 화면, 다크모드, 393×852.
- 홈 → 시금치 상세 → 날짜 다시 살펴보기 입력 단계.
- 격리된 데모에서 화면만 열었습니다. 카메라·사진·예시 라벨 인식, 날짜 수정, 소비 기록, 보관 변경, 저장은 실행하지 않았습니다.

## 화면별 점검

1. [홈](14-audit-home-393x852-dark.png) — 양호. 우선 살펴볼 3개와 포장지 날짜 확인 2개의 범위가 각각 제목에 표시됩니다. 식품 찾기, 식단 만들기, 날짜 확인 진입이 첫 화면에서 구분됩니다.
2. [시금치 상세](15-audit-spinach-detail-393x852-dark.png) — 양호. 날짜 의미(포장 소비기한), 출처(포장지 표시), 값(2026.09.02)이 한 카드에 모여 있고, 확인 안내와 `포장지에서 날짜 다시 확인` 동작이 바로 이어집니다. 소비 여부를 앱이 판정하지 않는다는 안내도 먹은 기록 동작 바로 옆에 있습니다.
3. [날짜 다시 살펴보기](16-audit-date-recheck-entry-393x852-dark.png) — 양호. 현재 기록이 유지되고 저장 전까지 바뀌지 않는다는 설명이 상단에 있습니다. 라벨 입력 방식이 선택된 상태와 입력→살펴보기→저장 순서가 보이며, 카메라·사진 선택은 주요 동작, 예시 결과는 별도 보조 동작으로 구분됩니다.

## 확인된 강점

- 추정 우선순위를 포장지 날짜나 소비기한으로 섞어 표시하지 않습니다.
- 지난 표시 날짜를 안전 판정으로 단정하지 않고, 포장지 날짜·보관·개봉 상태를 다시 살펴보도록 안내합니다.
- 상세의 현재 날짜·출처와 재확인 시트의 현재 기록이 연결되어 있어 어떤 기록을 검토하는지 알 수 있습니다.
- 날짜 재확인 화면의 닫기·입력 방식 탭·카메라·예시 결과 버튼은 모두 44px 이상입니다.
- 320/393px 및 라이트/다크 조합의 기존 Axe 날짜 재확인 테스트가 통과했습니다. 이번 실제 캡처 흐름에서도 브라우저 콘솔 오류는 없었습니다.

## 잔여 확인 한계

- 실제 카메라 권한·사진 선택·OCR 정확도·사용자가 날짜 의미를 고른 뒤 저장하는 단계는 열지 않았습니다.
- 이 점검은 화면과 접근성 자동 검사이며, VoiceOver/TalkBack, 확대 텍스트, 실제 사용자 이해도는 증명하지 않습니다.
- 홈의 검색·전체 식품 목록, 알림, 식단, 장보기 등 나머지 제품 흐름은 이번 범위에 포함하지 않았습니다.

## 다음 개선 기회

이번 경로에서는 기록 출처, 다음 행동, 저장 전 상태가 서로 맞아 추가 동작 변경의 근거가 충분하지 않았습니다. 다음 반복은 아직 점검하지 않은 식품 검색·날짜 확인 목록의 발견성과 필터 후 복귀 흐름을 실제 화면으로 확인하는 편이 효과적입니다.
