# 데모 라벨 결과 출처와 확인 순서

## 확인한 동작

데모의 라벨 예시는 OCR을 호출하지 않습니다. `시금치`, `2026.09.02`, 소비기한, 1개, 냉장 값을 미리 채우는 입력 연습용 동작입니다. 이전에는 버튼과 다음 결과 화면에서 실제 포장지를 읽은 값처럼 보일 여지가 있었습니다.

## 개선

- 버튼을 카메라 아이콘의 `샘플 라벨 인식`에서 문서 아이콘의 `예시 라벨 결과 보기`로 바꿨습니다.
- 결과 출처를 `예시 라벨 결과`로 표시하고, 실제 포장지를 읽은 값이 아니며 포장지와 날짜 종류·숫자를 대조해야 한다고 알립니다.
- 고정 저장 요약에도 `예시 결과 · 저장 전 확인`을 붙여 아래로 스크롤해도 예시 출처가 남습니다. 정식 런타임에서는 이 버튼이 계속 숨겨집니다.
- 예시 냉장 정보를 `포장지에 적힌 보관 방법`으로 표시하지 않고, 날짜 종류를 자동으로 사용자가 골랐다는 체크 표시도 하지 않습니다.
- 결과가 나타날 때 저장 버튼에 바로 포커스를 주지 않고 출처를 먼저 알립니다. 고정 저장 버튼과 포장지 날짜 입력이 겹치지 않도록 시트 내용을 출처로 스크롤하며, 날짜 종류를 바꾸면 키보드를 닫고 다시 확인할 수 있는 동작으로 포커스를 옮깁니다.

## 검증

- 라벨 결과·날짜 의미 변경·식품 선택·탭 복귀 관련 테스트 3개 통과.
- 320px에서 출처에 먼저 포커스하고, 날짜 입력이 고정 저장 버튼 아래에 가려지지 않는지 확인하는 모바일 테스트 통과.
- 라이트·다크의 날짜 재확인 Axe 검사와 정식 런타임에서 예시 버튼을 숨기는 테스트 통과.
- `npm run build` 통과: TypeScript, Vite 771개 모듈, 보호 런타임 28개 파일 통과.
- [날짜 재확인 입력 화면](05-date-recheck-example-button-393x852-dark.png), [예시 결과 상단](08-example-label-result-320x740-dark-readable.png), [예시 보관 정보와 확인 배지](09-example-label-result-review-320x740-dark-readable.png)를 직접 살펴봤습니다. 결과 화면은 격리된 데모 테스트에서만 열었고, 저장은 누르지 않았습니다.
- 남은 게이트: `npm run check:bundle` CSS 334.2KB / 예산 260KB로 실패합니다. 이번 UI 변경 때문에 예산 기준을 바꾸지 않았습니다.
